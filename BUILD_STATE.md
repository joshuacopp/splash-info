  continues to own production traffic on `splashcarwashes.info`
  regardless of staging state.
- **Rollback path:** comment out the staging `routes = [...]` blocks

- **Per-worker route patterns** are mirrored in the Deployed

## How this project is run

The work is split between two Claude surfaces:

- **Cowork** (planner) drafts briefs into `BRIEFS/`, maintains
  `BUILD_STATE.md`, and reviews outcomes after Claude Code executes.
- **Claude Code** (doer, runs in VS Code) reads `CLAUDE.md` +
  `BUILD_STATE.md` + a brief, makes the file edits, runs typecheck +
  build, fills in the brief's Outcome section, updates
  `BUILD_STATE.md`. Operates in headless mode via `claude --print`.

**Bridge:** `scripts/orchestrator.ps1` — a polling daemon the operator
launches once per work session. It watches `BRIEFS/QUEUE.md` and invokes
Claude Code headlessly when a brief is queued. On success the entry
moves to `BRIEFS/DONE.md`; on failure it moves to `BRIEFS/FAILED.md` and
the daemon halts. See `BRIEFS/README.md` for the full workflow + file
conventions, and `CLAUDE.md` at the repo root for the project rules
Claude Code auto-loads.

To start a work session:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/orchestrator.ps1
```

Stop with Ctrl+C. The daemon writes to `BRIEFS/orchestrator.log`.

(Use `pwsh` instead of `powershell` if you have PowerShell 7+ installed.
The operator's machine has only Windows PowerShell 5.1 by default, hence
`powershell` in the documented invocation.)

For one-off / manual brief execution without the daemon, open Claude
Code in the repo and paste:

```
Read CLAUDE.md, BUILD_STATE.md, and BRIEFS/<brief-filename>. Execute
the brief end-to-end. Fill in the Outcome section and update BUILD_STATE.md.
```

## Load-bearing constraints

These constraints are project-level. Treat as immutable; any brief that proposes touching them must be rejected without explicit operator override.

- **`/signup/{location}`, `/q/{location}`, `/join/{location}` URLs MUST NEVER change.** They are saved on hundreds of customer/admin device home screens as per-location bookmarks. Renaming them silently breaks the bookmark UX and is irreversible until devices are re-bookmarked manually. The signup-worker's `wrangler.toml` carries a warning comment immediately above the (commented) production-routes block; preserve it through any wrangler edits.
- **`pkg$` column name** in `pricing_simple`. See "Findings & decisions log" — kept as a quoted identifier; bracket-notation accesses (`row["pkg$"]`) are not to be normalized.
- **`SUPABASE_SERVICE_KEY` env-var name.** Legacy used `SUPABASE_SERVICE_ROLE_KEY`; the monorepo standardized on `SUPABASE_SERVICE_KEY`. Code reads the new name across all five workers. A binding set under the legacy name in Cloudflare results in a 401 on every authenticated read.
- **`manually_flagged` rows in `suspicious_phones`** are immutable from worker code. Auto-detection skips writes when the row has `manually_flagged = true`. Admin-curated deny entries (`'0000000000'`, etc.) stay untouched.
- **CF same-zone Worker-to-Worker subrequests must use service bindings, not URL fetches.** When apps/web (running on splash-web at staging/prod) does a URL-based `fetch()` to a sibling worker on the same CF zone, the request loops through the edge inefficiently and 522s after ~19s. apps/web SSR helpers (under `apps/web/app/**/_lib/worker-fetch.ts` and `_lib/me.ts`) call sibling workers via `env.<BINDING>.fetch(req)` instead, with a URL-based fallback for dev. The 5 service bindings are declared in `apps/web/wrangler.toml` (DASHBOARD_WORKER, SIGNUP_WORKER, PERFORMANCE_WORKER, SYSADMIN_WORKER, DAMAGE_WORKER) and merged into the global `CloudflareEnv` interface in `apps/web/cloudflare-env.d.ts`. Adding new server-side worker calls without the binding pattern reintroduces the 522. This is a CF runtime limitation; not negotiable.
